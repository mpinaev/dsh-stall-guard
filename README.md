# dsh-stall-guard

Плагин DeepSeek Harness, который отклоняет вызовы агента, где он сам себе
ставит срок или ждёт вхолостую. Одна проверка на конвейере инструментов, без
правок ядра и без правок промпта.

## Зачем

Агент любит оборачивать команды в `timeout 25` и ждать циклами `sleep 1`.
Первое рвёт операцию на середине: остановка docker бросается на полпути,
следующий шаг работает с недоделанным состоянием, а код возврата теряется.
Второе тратит время вместо проверки результата. Уговоры в инструкциях это
лечат не всегда — отказ в самом шаге, с причиной и заменой действия, лечит.

## Что ловит

| Инструмент | Условие | Почему отказ |
|---|---|---|
| `bash`, `pwsh` | `timeout N cmd` | Короткий срок рвёт операцию на середине, код возврата теряется. |
| `bash`, `pwsh` | `sleep N` | Ожидание циклом вместо проверки результата. |
| `job_output` | `wait: true` и `timeout_ms` больше 15000 | Блокирующее ожидание — те же десять минут по частям. О завершении фоновой задачи DSH сообщает сам. |
| `wait_agent` | `timeout_ms` больше 15000 | Уведомление о завершении приходит отдельным ходом, сидеть в ожидании незачем. |

Строчное написание `timeout` выбрано намеренно: `ConnectTimeout=5` у ssh и
`TimeoutStopSec=` у systemd не ловятся, потому что там другая буква и нет
пробела перед числом.

## Подключение

Плагин локальный, в npm не публикуется. Строка в патче профиля
(`~/.dsh/profiles/web/cordis.patch.yml`):

```yaml
- insert:
    - id: stall-guard
      name: /home/dragon/Projects/dsh-stall-guard/index.js
```

Перезапуск `dsh web` подхватывает строку. Без перезапуска живой экземпляр
перезагружается через `dsh_hot_reload` с `entryId: stall-guard`.

## Проверка

Проверить разбор команды, не поднимая хост:

```sh
node -e "import('./index.js').then(m => console.log(m.inspectCommand('docker ps -a')))"
```

Вживую: попросить агента выполнить команду с собственной обёрткой срока —
должен прийти отказ с причиной и подсказкой, что делать вместо.

## Границы

- Текст в кавычках не разбирается: `grep "timeout 5"` отклоняется, хотя это
  просто поиск. Цена ошибки — один переписанный вызов.
- Плагин не трогает `timeoutMs`, который модель передаёт в аргументах `bash`.
  Потолок этого значения задаётся в патче профиля (`bash-sandbox.maxTimeoutMs`).
- `promoteOnTimeout` живёт внутри пресетов агента, куда патч профиля не
  достаёт: команда, дожившая до потолка, может продолжиться фоновой задачей.

Подробности устройства — в [docs/DETAIL.md](docs/DETAIL.md).
