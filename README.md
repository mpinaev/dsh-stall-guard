# dsh-stall-guard

Отклоняет вызовы агента, в которых он сам себе ставит срок или ждёт вхолостую.
Небольшой локальный плагин DeepSeek Harness: одна проверка на конвейере
инструментов, без правок ядра и без правок промпта.

## Зачем

Агент любит оборачивать команды в `timeout 25` и ждать циклами `sleep 1`.
Первое рвёт операцию на середине: остановка docker бросается на полпути, и
следующий шаг работает с недоделанным состоянием, а код возврата теряется.
Второе тратит время вместо проверки результата. Уговоры в инструкциях это не
лечат — отказ в самом шаге, с причиной, лечит.

## Что ловит

| Инструмент | Что | Почему отказ |
|---|---|---|
| `bash`, `pwsh` | `timeout N cmd` | Короткий срок рвёт операцию на середине, код возврата теряется. |
| `bash`, `pwsh` | `sleep N` | Ожидание циклом вместо проверки результата. |
| `job_output` | `wait: true` с `timeout_ms` > 15000 | Блокирующее ожидание — те же десять минут по частям. О завершении фоновой задачи DSH сообщает сам. |
| `wait_agent` | `timeout_ms` > 15000 | Уведомление приходит отдельным ходом, сидеть в ожидании незачем. |

Строчное написание `timeout` выбрано намеренно: `ConnectTimeout=5` у ssh и
`TimeoutStopSec=` у systemd не ловятся.

Гейт монотонный (`ctx.tools.guard`): отказ нельзя переиграть другим слушателем
конвейера. Модель видит причину в том же шаге и переписывает вызов — обычно на
блокирующую команду или фоновое задание с уведомлением.

## Подключение

Плагин локальный, в npm не публикуется. В патче профиля
(`~/.dsh/profiles/web/cordis.patch.yml`):

```yaml
- insert:
    - id: stall-guard
      name: /home/dragon/Projects/dsh-stall-guard/index.js
```

Перезапуск `dsh web` подхватывает строку; без перезапуска можно перезагрузить
живой экземпляр через `dsh_hot_reload` с `entryId: stall-guard`.

## Проверка

```sh
node -e "import('./index.js').then(m => console.log(m.inspectCommand('docker ps -a')))"
```

Вживую: попросить агента выполнить `timeout 5 true` — должен прийти отказ с
причиной.

## Границы

- Текст в кавычках не разбирается: `grep "timeout 5"` отклоняется, хотя это
  просто поиск. Цена ошибки — один переписанный вызов.
- Плагин не трогает `timeoutMs`, который модель передаёт в аргументах `bash`;
  этот потолок задаётся в патче профиля (`bash-sandbox.maxTimeoutMs`).
- `promoteOnTimeout` живёт внутри пресетов агента, куда патч профиля не
  достаёт: команда, дожившая до потолка, всё ещё может продолжиться фоновой
  задачей.
